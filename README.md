# بازی دوز (Dooz)

پروژه کامل بازی فکری دوز با Angular و Tailwind CSS شامل نسخه‌های دوز ۳ تایی (کلاسیک و بی‌نهایت)، دوز ۹ تایی و دوز ۱۲ تایی با هوش مصنوعی سه‌سطحی و حالت دونفره محلی.

## پیش‌نیازها
- نصب بودن Node.js نسخهٔ ۲۲ یا ۲۴

## روش اجرا روی سیستم شما
1. فایل ZIP را از حالت فشرده خارج کنید.
2. ترمینال (Command Prompt / PowerShell / Terminal) را در پوشه پروژه باز کنید.
3. دستورهای زیر را اجرا کنید:

```bash
npm install
npm start
```

4. مرورگر را روی آدرس `http://localhost:3000` باز کنید.

`npm start` سرور بازی آنلاین را روی `127.0.0.1:4201` راه‌اندازی می‌کند و سپس Angular را اجرا می‌کند. درخواست‌های آنلاین از طریق پروکسی به همین سرور می‌رسند. با توقف دستور، هر دو سرور متوقف می‌شوند.

اگر Angular را مستقیماً با `ng serve` اجرا می‌کنید، در یک ترمینال دیگر ابتدا `npm run serve:online` را اجرا کنید. پس از تغییر تنظیمات پروکسی، Angular را دوباره راه‌اندازی کنید.

برای بررسی ساخت اتاق، پیوستن بازیکن دوم و همگام‌سازی حرکت‌ها، `npm run test:online` را اجرا کنید.

## نسخهٔ Android با Capacitor

کد Angular برای وب و Android مشترک است. خروجی موبایل فایل‌های محلی دارد؛ منو، هوش مصنوعی، بازی دونفرهٔ محلی، فونت و آیکون‌ها بدون اینترنت کار می‌کنند. سرور Node و SSR داخل اپ اندروید اجرا نمی‌شوند.

### ساخت و اجرا

۱. Node.js، Android Studio، JDK 21 و Android SDK 36 را نصب کنید. در Android Studio می‌توانید از JDK 21 همراه آن استفاده کنید. حداقل Android این پروژه نسخهٔ ۷ (API 24) است. برای تست، گوشی با USB debugging یا شبیه‌ساز لازم است.

۲. دستورهای زیر را در ریشهٔ پروژه اجرا کنید:

```bash
npm install
npm run android:sync
npm run android:open
```

پروژهٔ `android` را در Android Studio اجرا کنید. اگر پوشهٔ Android موجود نبود، ابتدا `npm run android:init` را اجرا کنید. پس از تغییر کد Angular، دوباره `npm run android:sync` بزنید تا فایل‌های تازه داخل پروژهٔ Android کپی شوند. دستور `npm run build:mobile` فقط بستهٔ وب موبایل را در `dist/mobile/browser` می‌سازد و به SDK اندروید نیاز ندارد.

### تنظیم بازی آنلاین موبایل

بازار و مایکت محل انتشار برنامه‌اند و سرور بازی آنلاین را میزبانی نمی‌کنند. بدون سرور، بازی آفلاین قابل استفاده است و تلاش برای اتصال آنلاین پیام در دسترس نبودن بازی آنلاین را نشان می‌دهد.

فایل `.env.mobile.example` را به `.env.mobile` کپی کنید. پس از آماده‌شدن سرور، آدرس واقعی HTTPS را وارد کنید:

```dotenv
DOOZ_ONLINE_URL=https://play.example.com
DOOZ_PUBLIC_WEB_URL=https://dooz.example.com
```

این آدرس‌ها نمونه‌اند. فیلد اول آدرس سرور بازی است؛ سرور یا پراکسی آن باید مسیر `/api/ws` را به WebSocket متصل کند. فیلد دوم اختیاری و آدرس نسخهٔ وب برای لینک دعوت است. بدون آدرس عمومی وب، دکمهٔ دعوت در موبایل کد اتاق را کپی می‌کند.

از `localhost` برای سرور گوشی استفاده نکنید؛ این آدرس به خود گوشی اشاره می‌کند. بستهٔ موبایل فقط آدرس HTTPS می‌پذیرد و از `wss` استفاده می‌کند. پس از تغییر آدرس‌ها `npm run android:sync` را دوباره اجرا کنید. این تنظیمات عمومی‌اند؛ کلید خصوصی، رمز یا اطلاعات محرمانه در آن‌ها قرار ندهید.

برای نسخهٔ وب، تنظیمات اختیاری در `public/runtime-config.json` هستند و در حالت پیش‌فرض همان سرور میزبان وب استفاده می‌شود. تنظیمات `.env.mobile` فقط روی خروجی موبایل اعمال می‌شوند.

### تست پیش از انتشار در بازار و مایکت

- نسخهٔ release را روی گوشی اقتصادی و میان‌رده با اینترنت خاموش تست کنید: فونت، آیکون‌ها، شروع بازی و حرکت هوش مصنوعی.
- چرخش صفحه، بریدگی نمایشگر، دکمهٔ برگشت، صدا و برگشت از پس‌زمینه را بررسی کنید.
- با دو دستگاه و اینترنت واقعی، ساخت اتاق، پیوستن، قطع اتصال و خروج از بازی را تست کنید.
- شناسهٔ فعلی `ir.dooz.game` در `capacitor.config.ts` یک شناسهٔ اولیه است؛ قبل از انتشار نخست آن را با شناسهٔ نهایی متعلق به خودتان هماهنگ کنید. اگر پروژهٔ Android از قبل ساخته شده، شناسهٔ `applicationId` و namespace آن هم باید هماهنگ شوند.
- خروجی فروشگاه باید release و با کلید اختصاصی شما امضا شود. کلید امضا و رمز آن را خارج از Git و در محل امن نگه دارید؛ برای به‌روزرسانی‌های بعدی لازم‌اند.
- مدل درآمدی هنوز انتخاب نشده است؛ فعلاً پرداخت، تبلیغات و خرید درون‌برنامه‌ای اضافه نشده‌اند. برای فروش امکانات داخل بازی، اتصال و تست واقعی SDK پرداخت هر فروشگاه مرحلهٔ بعدی است.

این مرحله پروژهٔ Android و بستهٔ موبایل را آماده می‌کند؛ ساخت APK امضاشده، تست روی دستگاه و انتشار فروشگاهی مراحل جداگانه‌اند.
