# بازی دوز (Dooz)

پروژه کامل بازی فکری دوز با Angular و Tailwind CSS شامل نسخه‌های دوز ۳ تایی (کلاسیک و بی‌نهایت)، دوز ۹ تایی و دوز ۱۲ تایی با شش حریف رباتی و حالت دونفره محلی.

## قابلیت‌های تازه

- «معمای روز» در صفحهٔ بازی: موقعیت یکسان برای همه با برد اجباری در دو حرکت، روز بر اساس ساعت ایران، ثبت تلاش‌ها و کارت تصویری نتیجه بدون افشای جواب. در Android کارت با پنجرهٔ اشتراک‌گذاری سیستم ارسال می‌شود؛ در وب امکان ذخیرهٔ PNG هم وجود دارد. کد `DOOZ-YYYYMMDD` را دوستتان در همان بخش وارد می‌کند؛ لینک وب از `online.publicWebUrl` ساخته می‌شود.
- هر دست کامل‌شده در بازی با ربات، دونفره روی یک دستگاه، آنلاین یا وای‌فای یک سکه دارد. موجودی روی همان دستگاه ذخیره می‌شود. در صفحهٔ شروع بازی، سختی، سبک بازی و شرط باز شدن همهٔ حریف‌ها دیده می‌شود. باران از ابتدا در دسترس است و سیمین، رستم، آذر، زال و سیمرغ با رسیدن موجودی به ۱، ۲، ۵، ۹ و ۱۵ سکه باز می‌شوند. سیمرغ دوز کلاسیک را تا پایان هر مسیر بررسی می‌کند و در دوز بی‌نهایت، ۹ و ۱۲ تایی جست‌وجوی عمیق‌تری دارد.
- بعد از باخت به ربات، بخش مربی موقعیت قابل بهبود را برای تمرین دوباره نمایش می‌دهد. تحلیل دوز کلاسیک دقیق است؛ پیشنهاد دوز ۹ و ۱۲ تایی تحلیل تاکتیکی است و تضمین برد ندارد. اگر اشتباه روشنی پیدا نشود، این موضوع صریحاً نمایش داده می‌شود.
- نشان‌های کسب‌شده و زنجیرهٔ حل معمای روز در پروفایل نمایش داده می‌شوند. راهنمایی و برگشت حرکت مانع دریافت نشان «روی پای خودت» هستند. حل معماهای آرشیوی زنجیرهٔ روزانه را پر نمی‌کند. پیشرفت در Android با Preferences ذخیره می‌شود.
- در ساخت اتاق آنلاین می‌توان رقابت خصوصی تا سه برد را انتخاب کرد. مساوی تعداد بردها را افزایش نمی‌دهد و پس از برد سوم رقابت پایان می‌یابد. سابقهٔ مشترک دو بازیکن در اتاق‌های بعدی هم دیده می‌شود.
- محیط‌های «حیاط فیروزه» و «میز خاتم» و سه صدای انتخابی چوبی، آرام و طنین سنتور در بخش ظاهر قرار دارند.

### نگهداری سابقهٔ رقابت آنلاین

سرور تاریخچه و شناسه‌های مهمان را در `.data/rivalries.json` ذخیره می‌کند. برای استقرار، `server.dataDirectory` را به یک پوشهٔ قابل نوشتن روی دیسک پایدار تنظیم کنید و از آن نسخهٔ پشتیبان بگیرید. فایل با نوشتن موقت، همگام‌سازی دیسک و جایگزینی ذخیره می‌شود؛ فقط یک نمونهٔ سرور باید به این پوشه بنویسد. اتاق‌ها و مسابقهٔ در حال اجرا در حافظه‌اند و با راه‌اندازی مجدد سرور برنمی‌گردند؛ تاریخچهٔ نتایج باقی می‌ماند. خطای ذخیره در رابط نمایش داده می‌شود و دادهٔ خراب هنگام راه‌اندازی بی‌صدا بازنویسی نمی‌شود.

هویت مهمان با توکن تصادفی صادرشده توسط سرور به دستگاه متصل است؛ سرور فقط هش توکن را ذخیره می‌کند. بازگشت به جای بازیکن قطع‌شده نیازمند همان هویت است. پاک کردن داده‌های برنامه، تعویض دستگاه یا پروفایل مرورگر هویت تازه‌ای ایجاد می‌کند؛ حساب کاربری و بازیابی بین دستگاه‌ها هنوز وجود ندارد.

برای بررسی: `npm test -- --watch=false` و `npm run test:online`. تست آنلاین از پوشهٔ موقت مستقل استفاده می‌کند و تاریخچهٔ واقعی را تغییر نمی‌دهد. پس از تغییر کد سرور، اجرای قبلی `npm run dev` را متوقف و دوباره اجرا کنید؛ سپس برای Android دستور `npm run android:sync` را بزنید. اشتراک‌گذاری سیستم باید روی گوشی واقعی هم تست شود.

## پیش‌نیازهای اجرا
- نصب بودن Node.js نسخهٔ ۲۲ یا ۲۴

## روش اجرا روی سیستم شما
1. فایل ZIP را از حالت فشرده خارج کنید.
2. ترمینال (Command Prompt / PowerShell / Terminal) را در پوشه پروژه باز کنید.
3. دستورهای زیر را اجرا کنید:

```bash
npm install
npm start
```

4. مرورگر را روی آدرس `http://localhost:3000` باز کنید.

`npm start` سرور بازی آنلاین را روی `127.0.0.1:4201` راه‌اندازی می‌کند و سپس Angular را اجرا می‌کند. درخواست‌های آنلاین از طریق پروکسی به همین سرور می‌رسند. با توقف دستور، هر دو سرور متوقف می‌شوند.

اگر Angular را مستقیماً با `ng serve` اجرا می‌کنید، در یک ترمینال دیگر ابتدا `npm run serve:online` را اجرا کنید. پس از تغییر تنظیمات پروکسی، Angular را دوباره راه‌اندازی کنید.

برای بررسی ساخت اتاق، پیوستن بازیکن دوم و همگام‌سازی حرکت‌ها، `npm run test:online` را اجرا کنید.

## تنظیمات پروژه

فایل `appsettings.example.json` را به نام `appsettings.json` در ریشهٔ پروژه کپی کنید و مقادیر همان فایل را ویرایش کنید. اگر فایل وجود نداشته باشد، برنامه از پیش‌فرض‌ها استفاده می‌کند. `appsettings.json` در Git و ZIP دانلود پروژه قرار نمی‌گیرد.

| بخش | کاربرد |
| --- | --- |
| `online` | `serverUrl` آدرس سرور آنلاین وب است. با مقدار خالی، وب از همان هاست استفاده می‌کند. `mobileServerUrl` آدرس اختصاصی Android است و اگر خالی باشد از `serverUrl` استفاده می‌کند. `publicWebUrl` آدرس نسخهٔ وب برای لینک دعوت و معما است. |
| `server` | `port` پورت سرور در استقرار و `dataDirectory` مسیر ذخیرهٔ داده‌هاست. |
| `development` | `webPort` پورت Angular در `npm start` و `onlinePort` پورت سرور محلی آنلاین است. |
| `android.billing` | `productId` شناسهٔ خرید دوز ۱۲ تایی و `myket.publicKey` و `bazaar.publicKey` کلیدهای عمومی RSA برای تأیید خرید هستند. کلید عمومی داخل APK قرار می‌گیرد. |

سرور وب را از ریشهٔ پروژه اجرا کنید و فایل تنظیمات استقرار را کنار `package.json` بگذارید. آدرس‌های بخش `online` در وب، با بارگذاری دوبارهٔ صفحه اعمال می‌شوند. تغییر پورت یا مسیر ذخیره به راه‌اندازی مجدد سرور نیاز دارد. تغییر تنظیمات Android به ساخت نسخهٔ جدید نیاز دارد.

برای سازگاری با استقرارهای قبلی، متغیرهای `PORT`، `DOOZ_DATA_DIR` و `DOOZ_ONLINE_PORT` روی مقدار متناظر فایل اولویت دارند. در ساخت Android، `DOOZ_ONLINE_URL` و `DOOZ_PUBLIC_WEB_URL` بر تنظیمات فایل اولویت دارند. فایل قدیمی `.env.mobile` وقتی استفاده می‌شود که فیلد آدرس متناظر خالی باشد. ویژگی‌های Gradle و متغیرهای محیطی قبلی کلید عمومی نیز همچنان پشتیبانی می‌شوند.

## نسخهٔ Android با Capacitor

کد Angular برای وب و Android مشترک است. خروجی موبایل فایل‌های محلی دارد؛ منو، هوش مصنوعی، بازی دونفرهٔ محلی، فونت و آیکون‌ها بدون اینترنت کار می‌کنند. سرور Node و SSR داخل اپ اندروید اجرا نمی‌شوند.

### ساخت و اجرا

۱. Node.js، Android Studio، JDK 21 و Android SDK 36 را نصب کنید. در Android Studio می‌توانید از JDK 21 همراه آن استفاده کنید. حداقل Android این پروژه نسخهٔ ۷ (API 24) است. برای تست، گوشی با USB debugging یا شبیه‌ساز لازم است.

۲. دستورهای زیر را در ریشهٔ پروژه اجرا کنید:

```bash
npm install
npm run android:sync
npm run android:open
```

پروژهٔ `android` را در Android Studio اجرا کنید. اگر پوشهٔ Android موجود نبود، ابتدا `npm run android:init` را اجرا کنید. پس از تغییر کد Angular، دوباره `npm run android:sync` بزنید تا فایل‌های تازه داخل پروژهٔ Android کپی شوند. دستور `npm run build:mobile` فقط بستهٔ وب موبایل را در `dist/mobile/browser` می‌سازد و به SDK اندروید نیاز ندارد.

### تنظیم بازی آنلاین موبایل

بازار و مایکت محل انتشار برنامه‌اند و سرور بازی آنلاین را میزبانی نمی‌کنند. بدون سرور، بازی آفلاین قابل استفاده است و تلاش برای اتصال آنلاین پیام در دسترس نبودن بازی آنلاین را نشان می‌دهد.

در `appsettings.json`، آدرس عمومی HTTPS سرور را در `online.mobileServerUrl` قرار دهید. سرور یا پراکسی باید مسیر `/api/ws` را به WebSocket متصل کند. اگر `online.publicWebUrl` خالی باشد، دکمهٔ دعوت در موبایل کد اتاق را کپی می‌کند. `localhost` در گوشی به خود گوشی اشاره می‌کند. پس از تغییر آدرس‌ها `npm run android:sync` را دوباره اجرا کنید.

### تست پیش از انتشار در بازار و مایکت

- نسخهٔ release را روی گوشی اقتصادی و میان‌رده با اینترنت خاموش تست کنید: فونت، آیکون‌ها، شروع بازی و حرکت هوش مصنوعی.
- چرخش صفحه، بریدگی نمایشگر، دکمهٔ برگشت، صدا و برگشت از پس‌زمینه را بررسی کنید.
- با دو دستگاه و اینترنت واقعی، ساخت اتاق، پیوستن، قطع اتصال و خروج از بازی را تست کنید.
- شناسهٔ فعلی `ir.dooz.game` در `capacitor.config.ts` یک شناسهٔ اولیه است؛ قبل از انتشار نخست آن را با شناسهٔ نهایی متعلق به خودتان هماهنگ کنید. اگر پروژهٔ Android از قبل ساخته شده، شناسهٔ `applicationId` و namespace آن هم باید هماهنگ شوند.
- خروجی فروشگاه باید release و با کلید اختصاصی شما امضا شود. کلید امضا و رمز آن را خارج از Git و در محل امن نگه دارید؛ برای به‌روزرسانی‌های بعدی لازم‌اند.

### خرید دوز ۱۲ تایی در مایکت و بازار

در پنل هر فروشگاه برای شناسهٔ برنامهٔ `ir.dooz.game` یک محصول درون‌برنامه‌ای **یک‌باره و غیرمصرفی** با شناسهٔ `android.billing.productId` ثبت کنید. مقدار پیش‌فرض `dooz_twelve_unlock` است. قیمت در همان پنل تنظیم می‌شود.

کلید عمومی RSA هر پنل را در `android.billing` کنار نام همان فروشگاه قرار دهید. ساخت release به کلید عمومی فروشگاه مربوط نیاز دارد.

```powershell
npm run android:sync
cd android
.\gradlew.bat :app:assembleMyketRelease :app:assembleBazaarRelease
```

خروجی‌ها در `android/app/build/outputs/apk` در پوشه‌های `myket` و `bazaar` قرار می‌گیرند. برای نصب یا انتشار، هر خروجی را طبق تنظیمات امضای برنامه امضا کنید. `:app:assembleStandaloneDebug` نسخهٔ Android بدون فروشگاه را می‌سازد. خرید و بازی دوز ۱۲ تایی در نسخه‌های فروشگاهی انجام می‌شود.

روی گوشی، خرید و لغو خرید را در هر فروشگاه امتحان کنید. سپس بازی آفلاین و بازیابی پس از نصب دوباره را با همان حساب فروشگاه بررسی کنید. راهنمای نصب SDK و تنظیم جداگانهٔ فروشگاه‌ها در [نمونهٔ رسمی مایکت](https://github.com/myketstore/billing-sample-android#store-configuration-manifest-placeholders) آمده است.

این مرحله پروژهٔ Android و بستهٔ موبایل را آماده می‌کند؛ ساخت APK امضاشده، تست روی دستگاه و انتشار فروشگاهی مراحل جداگانه‌اند.
